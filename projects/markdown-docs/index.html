02 · FOUNDATIONS SKILL

设计基础规范

用于建立或检查产品界面中的颜色、字体、间距、圆角与效果规则。

CORE PRINCIPLES

核心原则

查看原始 Markdown ↗
  1. 语义优先页面与组件优先消费语义 Token，不直接绑定基础值。
  2. 4px 网格先判断元素关系，再选择对应的间距尺度。
  3. 标准圆角只使用 0、2、4、6、8、12、999 七档标准值。
  4. 层级效果投影等级与界面层级对应，越临时、越聚焦，等级越高。
  5. 可读与无障碍文字、状态和反馈需要满足可读性与无障碍要求。
DELIVERY CHECK

交付检查

  • 变量命名可映射到代码
  • 语义变量已绑定基础值
  • 组件内没有孤立的 Hex、px 或临时效果值
  • 浅色与深色模式使用同名语义映射
  • 新增变量前确认现有语义无法表达
TOKEN FLOW

从基础值到应用

Primitive→Semantic→Component

让设计变量、组件属性与代码命名保持稳定映射。

05 · VISUAL AUDIT SKILL

Figma × Web
视觉走查

以 Figma 设计为基准，对齐线上页面状态，完成可复验的视觉验收、页面骨架标注和问题结构化记录。

AUDIT
WHEN TO USE

设计还原验收与问题闭环

适用于设计稿与线上页面找差异、页面标注和走查问题沉淀；默认只做检查、标注和报告，不直接修改设计稿或产品代码。

01CAPTURE

获取可比画面

统一视口、缩放、滚动位置和页面状态，保留原始证据。

02COMPARE

执行视觉走查

依次检查结构、栅格、间距、字体、颜色、图标与边界状态。

03ANNOTATE

生成 SVG 标注

在页面骨架原位放置稳定编号，确保问题可定位、可复验。

04REPORT

写入飞书 Base

记录当前表现、目标表现、P0–P3 优先级与坐标信息。

05VERIFY

完成与复验

汇总问题等级、交付链接和需要设计决策的待确认项。

01VISUAL EVIDENCE

SVG 页面骨架标注图

编号与问题记录一一对应，密集区域可局部放大，保留原始页面证据。

飞书多维表格问题库

统一记录页面区域、问题类型、现状、目标、优先级与复验状态。

06 · USER RESEARCH SKILL

启明星
用户调研

面向启明星安全运维平台开展模块级问卷研究，将用户证据转化为信息架构、任务流程、页面组织和交互体验优化建议。

START WITH明确调研模块
＋
DECISION GOAL明确设计决策

只有模块和目标明确后，才进入问卷设计、数据分析和体验诊断。

01范围与假设→02问卷与分流→03数据质量→04交叉分析→05设计诊断
01 / PLAN

调研方案与问卷

范围、目标、假设、样本、正式问卷、跳题逻辑、模块映射与分析计划。

02 / ANALYSIS

问卷数据分析报告

数据质量、样本结构、使用场景、痛点、满意度、群体差异与交叉验证。

03 / DESIGN

体验设计优化报告

用户任务、设计诊断、信息架构、流程与页面建议、优先级和验证计划。

EVIDENCE FIRST

区分数据事实、分析解释、原因推测、设计建议与待验证事项；关键结论至少由两类证据相互验证。

07 · ASSET DELIVERY

大屏静态资源交付

整理 Figma 静态资源、运行时资源与清单文件，明确哪些内容由切图承载、哪些内容由代码动态实现。

assets/dashboard/
dashboard/
├── source/      Figma 原始导出母版
├── runtime/     页面实现直接引用
├── manifest.json 资源编号与校验信息
└── README.md     使用与更新约定
DELIVERY RULES

使用约定

  • 页面代码优先引用 runtime
  • source 不直接修改，更新时从 Figma 重新导出
  • SVG 优化后保留 viewBox 并执行视觉回归
  • PNG 可转换 WebP / AVIF，但保留 PNG 回退
  • 文字、数字、图表和动画由代码实现
